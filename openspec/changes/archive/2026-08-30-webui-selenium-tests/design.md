## Context

Текущий проект brahma-webui предоставляет веб-интерфейс для регистрации и управления терминалами. Проект включает:
- Две формы: HTTP и gRPC для регистрации терминалов
- Две базы данных: gateway.terminals и processor.terminals
- Поиск терминалов по ID с отображением статуса

Необходимость тестирования возникает из-за отсутствия автоматизированного E2E тестирования веб-формы. unit-тесты покрывают логику, но не проверяют взаимодействие UI с бэкендом и двумя БД.

## Goals / Non-Goals

**Goals:**
- Автоматизированная проверка регистрации терминала через веб-форму
- Проверка сохранения в обеих базах данных (gateway.terminals и processor.terminals)
- Проверка удаления терминала через UI
- Проверка различия поведения HTTP и gRPC форм
- Проверка статуса Rejected для gRPC-зарегистрированных терминалов

**Non-Goals:**
- Нагрузочное тестирование
- UI-тесты для других модулей (gateway, processor)
- Тестирование API напрямую (без UI)
- Параллельный запуск тестов

## Decisions

**Выбор технологий:**
- **Selenium + Selenide**: Простота использования, хорошая документация, интеграция с Java 21
- **Firefox**: Указано в требованиях, стабильный драйвер
- **JUnit 5**: Стандарт для тестов в проекте (уже используется в других модулях)
- **TestNG**: Не используется, чтобы избежать дублирования фреймворков

**Структура проекта:**
- Отдельный Maven проект `brahma-webui-test`
- Пакет `com.example.brahmawebui.test`
- Ресурсы в `src/test/resources/`

**Подход к тестированию:**
- Каждый тест: полный цикл (подготовка → действие → проверка → очистка)
- Идемпотентность: тесты могут быть запущены многократно
- Изоляция: каждый тест использует уникальный ID терминала (TERM-00027)

**Конфигурация:**
- URL: http://minikube:30882/
- Таймауты: адаптивные (Selenide defaults)
- Headless mode: отключен (нужно видеть UI для отладки)

## Risks / Trade-offs

[Risk] Тесты могут быть хрупкими из-за асинхронности Kafka → [Mitigation] Адаптивные таймауты, ожидание состояний

[Risk] Изменения в UI могут сломать тесты → [Mitigation] Использование CSS-классов вместо XPath, модульная структура

[Risk] Параллельный доступ к БД при очистке данных → [Mitigation] Блокировка на время теста или использование уникальных ID

[Risk] Зависимость от внешнего сервиса (minikube) → [Mitigation] Локальный запуск тестов с моками при отсутствии инфраструктуры
